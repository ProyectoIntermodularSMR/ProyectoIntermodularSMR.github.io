Inyección SQL (SQLi)

Vulnerabilidad de Inyección de Código Web
ℹ️ Qué es

La inyección SQL (SQL Injection) es una de las vulnerabilidades web más críticas y comunes. Ocurre cuando una aplicación web no valida, filtra o sanea adecuadamente los datos que introduce el usuario en los formularios o URLs, permitiendo que un atacante interfiera en las consultas que la aplicación realiza a su base de datos subyacente.

⚙️ Cómo funciona

Cuando un formulario web concatena directamente las variables del usuario en una cadena de consulta SQL (por ejemplo: SELECT * FROM usuarios WHERE nombre = '$user'), el backend confunde los datos del usuario con sintaxis de comandos. Si el atacante introduce cadenas lógicas especiales como ' OR '1'='1, puede alterar por completo la lógica interna de la consulta, rompiendo las restricciones de autenticación del script de procesamiento.

⚠️ Qué puede hacer

Bypass completo del sistema de login (acceder como administrador sin contraseña), lectura y exfiltración de tablas completas de la base de datos (datos de usuarios, tarjetas, hashes de claves), alteración o borrado permanente de registros (sentencias UPDATE o DROP TABLE) e incluso, bajo ciertas configuraciones (como xp_cmdshell en SQL Server), la ejecución remota de comandos en el propio sistema operativo del servidor.

🛡️ Cómo prevenirlo
  • Utilizar de forma obligatoria Consultas Preparadas y Parametrizadas (Prepared Statements) en lenguajes de backend (como PDO en PHP). Esto separa estrictamente el código SQL de los datos aportados por el usuario.
  • Implementar el uso de ORMs modernos (como Hibernate, Entity Framework o Sequelize) que incluyen parametrización nativa por defecto.
  • Saneas y validar estrictamente todas las entradas de datos del usuario, aplicando listas blancas (Whitelisting) para tipos de datos específicos (como obligar a que un ID sea estrictamente un valor entero).
  • Aplicar el principio de mínimo privilegio en el gestor de bases de datos, asegurando que el usuario de la aplicación web no tenga permisos de superusuario (root/sa) ni capacidades de alteración de tablas globales.
🚨 Qué hacer si te attacked
  • Revisar los registros de errores del servidor web y de la base de datos para identificar el parámetro exacto o la URL vulnerable que está sufriendo los intentos de inyección.
  • Poner la aplicación web temporalmente en modo de mantenimiento para evitar el dump masivo de bases de datos mediante herramientas automatizadas como sqlmap.
  • Corregir la línea de código vulnerable sustituyendo la concatenación directa de variables por consultas preparadas.
  • Auditar la base de datos para comprobar si el atacante modificó datos, insertó nuevos usuarios administradores fraudulentos o comprometió otros archivos del servidor mediante el sistema de archivos de la base de datos.
